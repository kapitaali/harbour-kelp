# Progress — 2026-11-13

Branch `dev/0.2.0`. WS-C4 (stewards and channels), continuing from `PROGRESS-20261112.md`.

## Done

- **Bundle key in the pointer** (`7c1dfe3`). A channel link is only useful if a
  reader can open the bundle the pointer names, and that needs the bundle's
  content key. Nothing delivered it before. The signed pointer body now carries
  `key`, sealed for link holders only. A passphrase bundle must not back a
  channel: the pointer would bypass the passphrase. The UI has to enforce that.
- **Subscriber resolver** (`src/kelpchannelfetch.{h,cpp}`, uncommitted at the
  time of writing). Given a `kelpchannel://` link, asks each relay in turn for
  `GET /v1/channel/<id>`, opens the answer with the read secret, checks it
  against the channel id, keeps the newest verified pointer (`isNewer`), and
  reports an ordinary `kelp://` bundle link. The existing `KelpClient` fetches
  the bundle, so no new fetch path exists.
- Wired into the app as the `kelpChannelFetch` context property. No QML uses it
  yet.

## Review fixes made in this session

- The resolver did not reset `m_responseDone` between lookups. A previous
  lookup's flag could swallow the first failure of the next one, which would
