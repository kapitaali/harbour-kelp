## Public relay certificate

- A record `kelp.kapitaali.com` (TTL 300) added at nethost.fi, pointing at the
  relay's reserved address.
- Oracle ingress TCP 80 opened; firewalld `http` enabled permanently.
  Nothing listens on 80 except certbot's transient standalone challenge.
- certbot 4.2.0 installed in `/opt/certbot`, symlinked as
  `/usr/local/bin/certbot`.
- Production issuance succeeded (staging was in a maintenance window and its
  dry-run timed out on DNS; production was fine). Certificate valid to
  2027-02-02.
- Deploy hook installs `fullchain.pem` as `/etc/kelp-relay/cert.pem`
  (`root:kelp-relay 0644`) and the key as `key.pem` (`0640`), then restarts the
  service. `certbot-renew.timer` runs daily around 03:17 UTC.
- `KelpTls` previously loaded only the first certificate from the server PEM,
  so the relay sent a bare leaf. It now adds all following certificates with
  `SSL_CTX_add_extra_chain_cert`; the live relay verifies with code 0.
- Both ALPN protocols still negotiate: `http/1.1` for the gateway and `kelp/1`
  for the app tunnel.

## Relay name

- The baked default is now `kelp.kapitaali.com:9443` instead of the reserved
  address, because the browser gateway's certificate can only match a name.
  The app tunnel uses `SSL_VERIFY_NONE` + ALPN, so it is unaffected by the CA
  chain; the browser is the reason the chain fix matters.
- The emulator (a device-like guest) fetched `https://kelp.kapitaali.com:9443/`
  with curl and got 404 rather than a certificate error.
